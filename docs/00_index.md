# 00 — Documentation Index

This is the entry point to a 15-file technical reference set covering every
subsystem of the Coolattin Estate Records Explorer, generated by reading the
actual source code end-to-end (not by summarising `CLAUDE.md`). Each file
was produced independently and instructed to verify — not assume — every
claim in `CLAUDE.md` and in the other project memory it was given. Where a
file's own reading of the code disagreed with the project's existing
documentation, it says so explicitly rather than silently "correcting" it.

This means the set doubles as a documentation-drift audit: §2 below collects
every place where the running code has diverged from what `CLAUDE.md` (and,
in two cases, this doc set's own earlier drafts) claims. If you're
maintaining this codebase or citing its behaviour in the dissertation, read
§2 before you read anything else.

`docs/introduction.md` is a separate document (a dissertation Chapter 1
draft, academic prose) and is not part of this technical reference set.

## 2. Known issues surfaced while writing this doc set

Every item below was found by an agent actually reading the running code,
not inferred from comments. Severity is noted where it matters. This is not
an exhaustive bug list — it is a byproduct of documentation, not a security
or QA audit — but everything here is real and reproducible in the current
checkout as of 2026-07-28.

### Correctness bugs

- **All five registered analytics modules currently fail at runtime.**
  `analytics/registry.py`'s data-file resolution has a `Path.parents[2]`
  off-by-one that resolves above the repo root, and its candidate-path list
  never checks the actual seed-data location
  (`frontend/static/data/`). Every KPI/chart raises `FileNotFoundError`.
  `analytics/workhouse.py` is a 0-byte empty file and isn't registered at
  all. See `12_analytics_modules.md`.
- **`GET /api/townlands?county=X` is a no-op** — both branches of the
  route's if/else call the same underlying function regardless of the
  `county` param (a `# TODO` in the code confirms this is known). See
  `13_api_routes.md`.
- **`census_service._ingest_from_kg_or_seed()` never falls back to the CSV
  seed on a KG miss** during a live request, unlike `full_ingest.py` and
  `census_ingest.py`, which both do — a live KG outage returns zero
  records instead of degrading to seed data. See
  `03_data_ingestion_and_refresh.md`.
- **`_schedule_background_refresh()` in `census_service.py` is an
  intentional no-op stub.** Stale data is correctly flagged
  (`cache_status: stale_refresh`) but nothing ever actually refreshes it
  until an operator wires it to a real task queue. See
  `03_data_ingestion_and_refresh.md`.
- **The default Ask pipeline's Phase 6 fusion (`_fuse_lanes`) is
  permanently inert.** Stage 4.5 (GraphDB) only runs when `intent_route in
  (RELATIONAL, COMPARATIVE)`, but the default pipeline hardcodes
  `intent_route = "direct"`. Every request gets `graphdb_rows=[]`, so
  cross-source discrepancy detection never fires, contrary to how
  `CLAUDE.md` describes it. See `05_ask_pipeline_default.md`.
- **Direct memory reuse (legacy pipeline) has no effect on the live
  pipeline at all.** `_generate_sql` is called with `approved_examples=None`
  in the shipping code path, so `ask_query_memory` is written to (thumbs-up
  still records) but never read back to influence an answer. See
  `07_ask_pipeline_safety_execution_streaming.md` / `06_...routing.md`.
- **`GET /api/unified/workhouse-by-townland` and `GET
  /api/ask/estate-overview`** both run raw, inline SQL directly in the
  route handler, breaking the "SQL stays in repositories" convention
  stated in `CLAUDE.md`; the former also never returns a non-200 status —
  errors come back as `{"error": ...}` with HTTP 200. See
  `13_api_routes.md`.
- **The default local embedding provider may not run out of the box.**
  `sentence-transformers` / `torch` are commented out in
  `requirements.txt` (Azure App Service size constraint), so
  `EMBEDDING_PROVIDER=local` — the documented default — raises at runtime
  on a stock install unless those packages are installed manually. See
  `09_retrieval_and_embeddings.md`.
- **Two independent, incompatible writers of `data/source_snapshots/reconciliation_gaps.csv`** exist (`townland_service._write_reconciliation_gaps()`, single-column overwrite; `scripts/build_graph.py::write_reconciliation_gaps()`, five-column append-and-dedup) — the file on disk currently reflects whichever ran most recently. See `03_data_ingestion_and_refresh.md`.
- **`ask.js`'s client-side `progressOrder` has already drifted from the
  backend's actual SSE stage names** — some stages it expects to render are
  never emitted by `ask_service.py`; some stages the backend emits are
  never rendered. See `15_frontend_map_and_visualizations.md` and
  `07_ask_pipeline_safety_execution_streaming.md`.
- **Dead mobile-menu toggle and scroll-shadow effect** — `main.css` styles
  `#navBurger` / `.nav-wrap.scrolled`, but no JS anywhere wires up the
  interaction. No dark mode exists anywhere in the CSS despite the
  scaffolding pattern being present. See `14_frontend_pages_and_ui.md`.

### Security / access-control asymmetries

- **`POST /api/census/refresh` requires `ADMIN_API_KEY`; the equivalent
  `POST /api/townlands/refresh` (and `/api/townlands/wicklow/refresh`) do
  not.** Both trigger a forced external-KG refresh; only one is gated. See
  `03_data_ingestion_and_refresh.md` and `13_api_routes.md`.
- **SPARQL injection gaps**: `graphdb_sparql.py` interpolates the `county`
  parameter unescaped (currently safe only because all call sites pass a
  hardcoded value, not user input), and `semantic_layer._esc()` reuses a
  SQL-quote-doubling escaper in a SPARQL double-quoted string context,
  which is the wrong escaping rule for that grammar. See
  `11_external_integrations.md`.

### Documentation drift (CLAUDE.md / project memory vs. actual code)

These are corrections to *this project's own documentation*, not bugs in
the app:

- **Workhouse entity-resolution confidence thresholds are 0.75 / 0.60 /
  0.40**, not 0.85 / 0.70 / 0.50 as stated in `CLAUDE.md` and an earlier
  draft of `02_database_schema.md` (now corrected there). The scoring model
  uses `rapidfuzz.fuzz.token_sort_ratio`, not Jaro-Winkler, and does **not**
  score occupation overlap, family-size consistency, or household
  co-occurrence, despite those columns existing in the schema. See
  `04_workhouse_entity_resolution.md`.
- **GraphRAG node embeddings are 1024-dimensional, one per individual
  retrievable node** (Person, Townland, CivilParish, EmigrationEvent,
  EvictionEvent), not 768-dim one-per-community as an earlier draft of
  `02_database_schema.md` stated (now corrected there). See
  `10_knowledge_graph_retrieval.md`.
- **`voyage_embeddings.py` calls Cohere, not Voyage AI** — the module's own
  docstring says so directly ("replaces Voyage AI"); the misleading
  filename is legacy. The actual default embedding provider is `local`
  (BAAI/bge-large-en-v1.5), not Cohere. See `09_retrieval_and_embeddings.md`.
- **`config.py`'s `EMBEDDING_PROVIDER` and `VRTI_REQUEST_TIMEOUT` fields
  are both dead code** — the real provider selection reads `os.environ`
  directly in `voyage_embeddings.py`, and `vrti_sparql.py` never imports
  `config` at all, hardcoding its own 30s timeout that happens to match the
  documented default. See `09_retrieval_and_embeddings.md` and
  `11_external_integrations.md`.
- **The VRTI five-minute offline cooldown lives in `ask_service.py`**
  (`_VRTI_UNAVAILABLE_COOLDOWN`), not in `vrti_sparql.py` where its own
  integration doc initially looked for it. See `11_external_integrations.md`.
- **"Thirty-plus metrics" in the semantic layer refers to superseded
  template IDs each metric subsumes, not the metric count itself** — the
  actual `METRIC_REGISTRY` has 13 top-level metrics. See
  `08_semantic_layer.md`.
- **The Ask pipeline's keyword lists in `CLAUDE.md` are all incomplete**
  relative to the real `intent_router.py` source — e.g. ANALYTICAL's
  `output_mode` set is `{count, aggregate, trend, list, grouped}`, not
  `{count, aggregate, trend}`. Full verbatim lists with diffs are in
  `06_ask_pipeline_legacy_and_routing.md`.
- **CLAUDE.md names a `_synthesize_answer()` function that does not
  exist** — the two pipelines actually use two different functions
  (`_claude_synthesize_answer` vs `_generate_rephrased_answer`) with
  different prompts and gate semantics. See
  `05_ask_pipeline_default.md` / `07_ask_pipeline_safety_execution_streaming.md`.
- **ANALYTICAL route does use free-form LLM SQL** on four distinct
  fall-through conditions, contrary to CLAUDE.md's "never." See
  `06_ask_pipeline_legacy_and_routing.md`.

## 3. How this set was produced

Files 01 and 02 were written directly by reading `app.py`, `create_app.py`,
`config.py`, `extensions.py`, and the relevant repository files in full.
Files 03–15 were each produced by an independent agent instructed to read
its assigned source files in their entirety (not grep excerpts), ground
every claim in code actually read, and explicitly flag — not silently
paper over — any disagreement with `CLAUDE.md` or with a sibling document.
Numeric thresholds, function names, and table schemas were cross-verified
across files where their territory overlapped (e.g. the entity-resolution
thresholds in 02 vs. 04, the embedding dimension in 02 vs. 10). Where two
documents disagreed, the one that actually read the defining source file
was treated as authoritative and the other corrected — see §2.
